# 射击热量开发文档

首期对象为 RoboMaster 2027 赛季高校联盟赛（RMUL）3V3 步兵机器人。研究对象是裁判系统判定的射击热量，当前版本提供裁判回传热量的只读监测，用于日志和状态显示。

## 规则依据

采用《RoboMaster 2027 机甲大师高校联盟赛比赛规则手册》V1.0.0（2026-10-15）作为调研起点。步兵热量上限、冷却规则及其适用条件待按该赛季条款核实。车端能读到哪些字段、各字段何时更新，需另行对照对应版本的裁判系统通信协议和步兵工程。[官方规则资料中心](https://bbs.robomaster.com/wiki/20204847/1969150)

## 步兵方案比较

| 热量信息来源 | 可以核对的事实 | 选型前需要确认 |
| --- | --- | --- |
| 裁判回传 | 最近一帧上报的热量 | 步兵车端是否收到该字段，两次更新实际相隔多久 |
| 本地估算 | 按比赛规则从本地事件记录推算的热量 | 记录对应操作指令还是实际观测，能否从日志区分 |
| 回传与估算对照 | 同一时段内两条热量记录的差异 | 能否对齐时间，区分报文延迟与估算偏差 |

先以裁判回传作为对照基准。若已有步兵日志，优先核查连续报文的接收时间和热量值。接收时间只能说明数据何时到达车端；比较两条记录时，还需确认它们分别对应哪个时刻。本版直接比较回传的热量与上限，保留两者各自的时间信息。

## 首版接口与验证

`heat_monitor_compare` 接受同一机器人、同一热量通道的热量和上限两项已解码读数。输出为数据缺失、数据过期、低于上限、等于上限或高于上限，供日志与显示使用。等于上限描述数值关系，比赛判罚以裁判为准。此版本范围限于只读监测。

调用方为每项读数保存数值、接收标志与接收时间，并根据各自报文的实际周期给出有效期（毫秒）。有效期包含截止时刻。比较使用同一单调毫秒时钟上的一致快照；首帧前、重启及重新建立会话时清除接收标志。快照的实际年龄应小于一个完整的 32 位毫秒计数周期。模块按值接收数据，没有共享可变状态。

在本目录用 `gcc -std=c99 -Wall -Wextra -Werror -I. heat_monitor.c tests/test_heat_monitor.c -o heat_test` 编译，再运行生成的程序。测试覆盖缺帧、两路独立过期、有效期边界、三种数值关系及计时回绕。固件联调需要用实际报文核对时间和字段映射。

## 后续共用

后续目标是让其他兵种复用经步兵验证的热量处理逻辑。接入第二个兵种时，用两者的规则条件和实际数据来源核对共用范围。当前只记录步兵需求，兵种专属参数随其适用条件登记。
