# 射击热量开发文档

首期对象为 RoboMaster 2027 赛季高校联盟赛（RMUL）3V3 步兵机器人。模块提供两条可分别记录的热量数据：裁判上报的热量，以及依据枪管开关已确认计数得到的当前热量估计。两者均供日志和状态显示使用。

## 规则依据

采用《RoboMaster 2027 机甲大师高校联盟赛比赛规则手册》V1.0.0（2026-10-15）作为调研起点。步兵热量上限、冷却规则及其适用条件待按该赛季条款核实。车端能读到哪些字段、各字段何时更新，需另行对照对应版本的裁判系统通信协议和步兵工程。[官方规则资料中心](https://bbs.robomaster.com/wiki/20204847/1969150)

## 步兵方案比较

队伍已确认本车枪管装有弹丸通过检测开关。当前需求是在下一帧裁判热量到达前，先根据已通过弹丸估计此刻的热量。开关记录的是弹丸经过检测点的时刻，裁判报文的车端接收时间记录的是报文到达时刻。模块接收已确认的计数，开关的硬件采集与实车验证待接入。

| 热量信息来源 | 可以核对的事实 | 选型前需要确认 |
| --- | --- | --- |
| 裁判回传 | 最近一帧上报的热量 | 步兵车端是否收到该字段，两次更新实际相隔多久 |
| 本地估算 | 枪管开关提供实际通过数量，可作为本地事件记录 | 固件如何记录计数和时间，以及实测计数是否有重复或遗漏 |
| 回传与估算对照 | 同一时段内两条热量记录的差异 | 能否对齐时间，区分报文延迟与估算偏差 |

以裁判回传作为对照基准。若已有步兵日志，优先核查连续报文的接收时间和热量值。比较两条记录时，还需确认它们分别对应哪个时刻。保留裁判热量与上限各自的接收时间。

## 枪管开关热量估算

[`heat_estimate.h`](heat_estimate.h) 提供一个按事件时间更新的估算器。每个实例负责同一会话、同一通道。初始热量、每次通过对应的热量、每秒冷却值均由使用方提供。测试中的数值是人工样例。

1. 用 `heat_estimate_begin` 登记一个已对齐的起点。起点热量必须已包含该时刻的累计计数。例如日志从已确认的零热量时刻开始，就登记零热量和该时刻的实际计数。中途接入且只有接收时间时，无法从一帧报文推断它已包含哪一次开关事件，估值应保持不可用。
2. 用 `heat_estimate_observe` 按发生顺序提交开关累计计数及其毫秒时间戳。模块先按上个区间的速率扣除已经过时间内的冷却量，最低为零，再记入本次确认事件。同一计数重复上报不会重复增加热量，同一毫秒的连续两个计数可以分别记入。冷却速率变化时，也应在其生效时刻提交当前计数及新速率。
3. 用 `heat_estimate_read` 读取截至给定时刻、基于已提交事件的当前估值，输出单位为千分之一热量。读取不会消耗事件或更新状态。到达一帧裁判数据时，可同时记录回传值和本地估值；仅知道报文接收时间时直接覆盖估值，可能把已入账的事件抹掉。

调用方由一个任务串行处理记录和查询。ISR 采集时，累计计数与事件时间须作为一条完整记录交给该任务；每个已确认事件都需要自己的时间戳。计数跳号或事件乱序会使估值失效，可从下一个已知对齐起点重新开始。32 位毫秒时钟和计数器均支持自然回绕，有效时间间隔须短于半个时钟周期。设备重启或计数器重新初始化后另起会话。开关的重复触发若已在采集端计成两个不同序号，估算器无法据此识别为同一发。

## 裁判回传与验证

`heat_monitor_compare` 接受同一机器人、同一热量通道的热量和上限两项已解码读数。输出为数据缺失、数据过期、低于上限、等于上限或高于上限，供日志与显示使用。等于上限描述数值关系，比赛判罚以裁判为准。此版本范围限于只读监测。

调用方为每项读数保存数值、接收标志与接收时间，并根据各自报文的实际周期给出有效期（毫秒）。有效期包含截止时刻。比较使用同一单调毫秒时钟上的一致快照；首帧前、重启及重新建立会话时清除接收标志。快照的实际年龄应小于一个完整的 32 位毫秒计数周期。模块按值接收数据，没有共享可变状态。

在本目录分别编译并运行两个测试程序。

```sh
gcc -std=c99 -Wall -Wextra -Werror -I. heat_monitor.c tests/test_heat_monitor.c -o heat_test
gcc -std=c99 -Wall -Wextra -Werror -I. heat_estimate.c heat_monitor.c tests/test_heat_estimate.c -o heat_estimate_test
```

回传测试覆盖缺帧、两路独立过期、有效期边界、三种数值关系及计时回绕。估算测试覆盖计数去重、同毫秒多事件、迟到裁判报文、冷却到零、冷却速率变化、计数和时钟回绕，以及记录不完整后的重新建立基准。实车仍需核对开关记录与裁判数据的时间关系、事件完整性和规则字段。
